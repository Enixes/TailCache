# Predictor implementation review — before qualification, 18 November 2026

The workload/runner are separate Java classes, compiled from JAR dependencies into `build/predictor-20261118`; old retained class directories are unchanged. The scalar generator uses independently salted index hashes for keys and Bernoulli write decisions. It retains no finite trace or cached-payload bank and carries one monotonic operation counter across all phases. Actual writes are counted, not asserted to be an exact nominal ratio. Ordinary cache access, immutable fresh values and checksum consumption match the earlier API contract; extra generator CPU cost and new logging are explicit treatment differences.

JAR-only compilation of39 main/helper sources and the bounded paired functional JVM pass. Five write ratios cover2.2 million deterministic positions each, uniform key coverage and paired reads/writes; both cache backends agree over three continuous logical phases at0/5% writes and retain correct residents/versions. Analytics disabled; original bounded-default/tiering parameters inherited. Two additional bounded runner smoke JVMs check 0% Caffeine and5% Chronicle complete phases, empty-update handling and valid output. They retain cold-compiler/missing-native-scope warnings and are functional checks, not performance evidence. Timed recorder source is identical to the geometry runner after workload-type normalization. No performance result is claimed from these checks.

The phase runner retains every-operation HDR service/response/gap/read/update and sparse stalls, intended-arrival no-skip accounting, allocation/churn/compiler counters and fixed memory. It adds only outside-envelope stream-position records and removes cursor reset. Separate G1 age logging is retained for qualification; both backends use identical flags. Empty update distributions at0% are preserved, not treated as invalid observations. Independent auditing decodes raw HDRs, reconciles GC/RSS/source and independently replays full scalar write counts from seed/phase windows.

The driver freezes source/runtime/model and per-slot timing, maintains immutable slots and a fixed counterbalanced schedule. An eighteen-fork qualification ceiling covers12/60/optional120-second warmup at0/0.5/5% writes; the30-fork validation is separate and uses three declared seeds. Model predictions read only GC/schedule/backend and are written before the scoring stage. Controls, negative predictions and all warnings remain included. Source cannot change during a cohort. No successful-only retries, hidden payload sweep or pooled percentile.

Offline model tests cover a known pause, below-budget behavior, window edges, overlapping intervals, same-total/different-shape pauses and invalid inputs. Controller tests cover30-slot pairing, the low-write pilot, empty zero-write channels and failure retention. Recovery tests preserve ordinary-usage, active-thread/driver and duplicate-turn guards. The original Argon equation and the finite-window/additive-baseline extension remain approximate development models, with all-fork numerical errors and naive winner baselines disclosed. Their freeze is not external preregistration or human peer review.

Known limits to retain: implicit timing generator cost, spin pacing, periodic GC policies, few forks, fixed heap/collector and host. Late-window occupancy/compiler diagnostics do not prove steady state. G1 age/old-region evidence does not identify every object's provenance. Conditional GC-based reconstruction is not an ex ante GC/crossover predictor. A failed forecast is a valid scientific result.
