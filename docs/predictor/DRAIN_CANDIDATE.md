# Secondary queue-drain candidate — frozen after pilot, before holdout unblinding

18 November 2026. The primary M0/M1 algorithm, before-run0.5–2% forecast,30-fork validation and source remain unchanged. This is a **pilot-derived secondary analysis**, specified while the primary validation is collecting, before its response values/GC outcomes are inspected. It is not a model declared before the primary collection began. Do not relabel it as the original forecast or external preregistration.

Motivation: the eighteen-fork pilot gives correct M1 response-p99.9 winner directions in9/9 pairs but large all-fork numerical error, especially close to the0.1% pause budget. Low utilisation alone does not guarantee negligible queue drain near a percentile boundary. A pause can delay requests after it ends; omitted drain may therefore change whether a quantile enters the pause regime.

M2 is a deterministic FIFO server simulator with fixed operation service cost and fixed recording/bookkeeping cost. Pauses suspend either kind of work; arrivals follow the retained50k/s schedule, no jobs are skipped, and backlog is drained. Compute simulated per-job completion-minus-intended-arrival, quantize to the same three-significant-digit HDR bins, and add M1's already frozen timer-only q-specific allowance. This remains a constant-cost/GC-conditioned approximation, not a new GC forecasting law.

## Parameters fixed without primary-validation targets

- Intrinsic service cost at0/0.5/5%: mean of the pilot120-second-warmup service bins whose upper bound is <=100µs, separately for each backend. This truncation estimates non-pause CPU work; it does not remove any observations from experimental results or numerical scoring. Interpolate service costs piecewise at1/2%; use every120-second pilot fork, including warnings.
- Fixed bookkeeping cost per backend: median across the three pre-existing17November4KiB/zero-ballast saturated primary forks of `(windowNs - GCpauseOverlapNs)/operations - intrinsicServiceMeanNs` with the same100µs definition. Negative median is an invalid calibration, not a licence to tune it. The old/new recorder body was checked identical after workload-type normalization; source differences within cache operations are captured by the new pilot service costs.
- Timer allowance is exactly M1's frozen timer calibration. No parameter is fitted to the new primary validation's response, service or GC data. Inputs, costs and code hashes accompany the candidate.

## Evaluation and worth rule

After all primary collection and audits, first finish/retain the original M0/M1 score. Then write immutable M2 predictions using only its frozen calibration, each new fork's GC intervals/phase schedule and declared write ratio. Score against response quantiles separately. Report every fork/error, model prediction input hashes, all naive baselines, warnings, absolute/relative/log errors and coverage. The original failed/supported forecast is unchanged.

Permit **one additional fresh12-JVM validation** (0/0.5/5% writes × two backends × two new paired seeds) only if M2's primary-validation median absolute p99.9 error is at least25% smaller than M1 and its p90 absolute error is no more than10% worse. This is an adaptive model-development decision, not confirmatory evidence from the first30. Freeze M2 and the fresh-seed schedule before launching those12; use identical measured classes and retain the original120-second/transient qualification warning. If the rule fails, stop expansion and report the failure. No repeated model fitting until success, no successful-only JVM replacements or pooled quantiles.

Known omissions: variable service costs, non-GC pauses, cache/GC feedback generated by changing the server model, and GC events beyond the observed measurement envelope. The model cannot establish that every observed delay was caused by GC. A successful numerical reconstruction is conditional on observed pauses. Higher-percentile results retain finite-support limits.
