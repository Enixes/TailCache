Pilot001 stopped after its35th fresh fork, b1-allocation-p256-live301989888-f1-CAFFEINE, exit0/host pass. The parser required16 physical entries for every secondary metric. Allocation rate/norm and gc.count each have16 entries; gc.time has14. Indexed JMH text shows absent gc.time exactly in physical iterations4 and13, whose gc.count values are zero. Original raw JSON/text, hashes, source archive and terminal manifest are retained. The first34 forks passed but the complete pilot is not accepted.

Primary JMH1.37 GCProfiler source emits gc.count every iteration, but emits gc.time only when count or time changes (lines127–138): https://github.com/openjdk/jmh/blob/1.37/jmh-core/src/main/java/org/openjdk/jmh/profile/GCProfiler.java#L127-L138 . Therefore rawData for gc.time can be sparse, with no iteration index. This is a parser contract defect, not evidence that GC time was missing from a fork with known no-GC intervals. Count zero alone cannot prove which slots omitted a time-only change, so do not blindly zip with nonzero counts.

A count-positive missing time, shifted/duplicate/missing iteration header, changed count, unmatched metric length/value or unknown profiler version fails closed. Retain original sparse metrics, reconstructed full physical vector and explicit zero-filled iteration indices; derive analysis only from last8 fixed windows.
