The source-controlled Java21 RecordingFile reader projects only fields the Python aggregate consumes. It retains every selected Java/native sample and new-/outside-TLAB allocation event, all recorded frames, raw internal class names, method descriptors/frame type/line/bytecode position, stack truncation, precise timestamps, both thread IDs/name and allocation class/sizes. Raw getString("name") is necessary: RecordedClass.getName() replaces slash separators with dots, unlike the standard JSON exporter. No worker/phase/event-rate selection occurs in the exporter. One event is streamed at a time with a4Mi-character bound and a256MiB Java heap; stdout is not captured wholesale or written as a giant intermediate dump.

CLI and RecordingFile event ordering can differ, so event multiset comparison preserves multiplicity without assuming sorting.

Python retains every event in an aggregate grouped by actual worker/other/missing thread, event kind and complete warmup/conditioning/measurement/setup-between-teardown intervals. Worker ownership requires both positive Java/native IDs and matching name; conflicting partial identities fail closed. Intervals must be nonoverlapping. Events within the maximum observed GC-clock residual of any interval boundary are counted and flagged, never dropped. That residual is empirical clock fit evidence, not a proven absolute error bound. Full stack signatures and top/inclusive method counts are retained; recursive frames count once per inclusive event. Null/truncated stacks and allocation classes/triggering-object bytes/TLAB capacity are explicit. TLAB triggering-object bytes are not a total allocation census; CPU sample counts are not independent latency replicas, exact method time or measured stall duration.
