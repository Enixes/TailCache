When the faster cache call gives the slower response

At 4 KiB and the same 5% write rate, Caffeine led when writes targeted a small set of keys. Chronicle led when updates reached across the cache. Compare what happened to the calls, the requests waiting for them, and the garbage collector.

Where writes land

The cache always held 32,768 entries. Reads could access any key. Only the eligible write set changed between the two groups.

Value size changes the call-time winner

A hit on Caffeine returns the stored array. Ordinary Chronicle reads allocate a Java array and copy in the value. The relative cost changes with value size and with which part of the latency distribution you examine.
